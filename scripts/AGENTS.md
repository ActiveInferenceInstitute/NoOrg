# Validation scripts

The scripts in this directory are deterministic repository gates. They inspect tracked source and documentation without changing product files.

- `gate.ts` declares every arm of the `./run.sh` entry point, runs the arm's commands, and generates `docs/_generated/gate-timings.md` in report mode.
- `validate-repository.ts` checks tracked-file policy, unfinished implementation markers, prohibited vocabulary, and source-tree writes.
- `validate-contracts.ts` checks that public scheduler methods, HTTP routes, state versions, configuration variables, and manuscript extension claims remain aligned.
- `validate-decisions.ts` checks evidence-boundary decision records.
- `units-manifest.ts` provides check, diff, and explicit update modes for corpus integrity review.
- `generate-openapi.ts` generates and checks the tracked HTTP contract.
- `validate-docs.ts` checks relative Markdown links.
- `gnn-conformance.py` installs the parser revision pinned in `.github/gnn-pin.json` and checks GNN sketches or the pinned exemplar.
- `container-check.sh` builds the committed image and waits for its `/ready` probe.

The active roadmap is an explicit planning surface and is exempt from the unfinished-marker scan; completed items must still be removed from it rather than marked complete indefinitely.

## Rules

- Declare an arm once, in `gate.ts`, and have it call an npm script from `package.json` or a script in this directory. Do not repeat a command inside a composite arm.
- Composite arms must reference other arms, so `./run.sh all` cannot drift from its parts.
- Keep measured numbers in `docs/_generated/` generated by a script; never write them into prose by hand.
- Keep the live provider and container checks out of `fast` and `all`.

Run gates through `./run.sh <arm>`, or the corresponding `npm run validate:*`, `npm run units:manifest:*`, `npm run api:openapi:*`, and `npm run manuscript:*` commands for a single step.
